Prototype overview

Representative scores for every agent, without session-length selection bias.

Select a deterministic simple random sample inside every tenant/agent population. Lock that membership first. Use token cost only to pace execution afterward.

Core contract

Selection and execution are separate decisions.

This is the crucial change from token-constrained packing. Costs cannot decide whether a session belongs in an agent's reporting sample.

Scope: agent-level reporting only. This prototype deliberately does not calculate a fleet-level metric.

Tenant

An organization, such as Contoso or Fabrikam.

Agent

An application inside one tenant, such as Support or Sales.

Stratum

One tenant/agent pair. It has its own eligible population and sample.

Sample

A fixed-count uniform random selection inside one stratum.

Uniformity guarantee

Every session inside an agent gets the same chance.

For agent a:
eligible population = N_a
sampled sessions = n_a

inclusion probability for every eligible session:
p_a = n_a / N_a

A deterministic SHA-256 rank uses the reporting seed and the tenant, agent, session ID, and version. It intentionally does not use session token cost. Selecting the first n_a ranks is simple random sampling without replacement.

Changing only cost cannot change sampled IDs because cost is excluded from rank construction. Cost affects only queue timing after membership is already fixed.

End-to-end method

One reporting period, five explicit stages.

01

Freeze population

Build each agent's eligible session list, excluding duplicate and already processed versions.

02

Sample uniformly

Assign stable random ranks inside each tenant/agent and select the fixed count.

03

Persist metadata

Save N_a, n_a, p_a, seed, selected IDs, and status.

04

Pace execution

Use estimated tokens only after selection to reserve work under the rolling TPM limit.

05

Report per agent

Use completed selected results to report each agent's mean score and normal-approximation interval.

Large items

Oversized sessions remain visible.

A selected session whose estimated cost exceeds the rolling TPM limit is marked OVERSIZED. It remains part of the selected sample and is never replaced by a shorter session, preserving cost-independent membership.

Bounded backlog

Excessive delay is explicit.

An optional schedule-delay limit marks a selected item DROPPED when its greedy earliest budget-compliant start would exceed the limit. The item remains in the selected sample record and is never replaced.

Agent report

Selected versus completed.

Each agent report includes both selected count and completed count. Mean score and a finite-population-corrected normal-approximation 95% interval use completed selected sessions only. A completed census has a zero-width interval.

Durable metadata

Queue records sampling context for auditability.

Queue JSON stores per-stratum seed, N_a, n_a, p_a, and selected request IDs. Item states are PENDING, SCHEDULED, COMPLETED, OVERSIZED, or DROPPED.
