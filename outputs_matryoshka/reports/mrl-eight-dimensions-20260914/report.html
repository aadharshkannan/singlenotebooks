What did we test?

Can we make full-session embeddings much smaller without making the sampling-and-prediction result worse? We changed only the vector representation in the comparison: the embedding source, reference labels, sampling rules, scoring rules and replay settings stayed matched.

  1. Represent a session
    Build bounded evidence from its conversation and tool activity.
  2. Embed and shorten
    Generate 1,536 values, keep the first d, then re-normalize.
  3. Sample and estimate
    Select sessions; use their known reference labels to estimate the rest with IDW.
  4. Measure error
    Compare estimates with reference labels on unselected sessions.

The native model and the exact shortening method

The native embedding model was OpenAI text-embedding-3-small, used through Azure OpenAI / Foundry. It converts the session evidence into a list of 1,536 numbers: the vector's dimensions. OpenAI documents native shortening support linked to Matryoshka Representation Learning. The idea is that useful shorter representations are nested inside the larger vector; whether a particular size is sufficient still depends on the task.

At 8 dimensions, we kept coordinates 0 through 7, in their original order. We then divided the shortened vector by its Euclidean (L2) length:

short = full_embedding[:d]
short = short / np.linalg.norm(short)

No PCA, SVD, Gaussian random projection, coordinate sorting or retraining was used. All shortened vectors came from the same saved full-dimensional embeddings. Tested sizes: 1,536 → 512 → 256 → 128 → 64 → 32 → 16 → 8.

What does “performance” mean here?

The main measure is mean absolute error (MAE) on sessions that were not selected. For each one, we compare its predicted task-completion probability with its stored binary label, then average the absolute differences. Lower is better; zero means perfect predictions.

For example, predicting 0.8 when the reference label is 1 produces an error of 0.2. This differs from binary accuracy, which first thresholds the prediction at 0.5. Known selected-session labels are excluded from the headline MAE, so they cannot make it look artificially better.

Each dataset used 30 shuffled orders under 5 arrival patterns (evenly spaced, random timing, bursty, front-loaded and agent-blocked), at sampling budgets of 1%, 2%, 5%, 10%, 20%. The same seeded order was used across dimensions for a fair comparison. Each replay contains every source session once.

These reruns reuse the same sessions and labels. They test sensitivity to ordering, not new populations or independent judge reliability. What the averages do not tell us

For example, at a 20% sampling budget in Cosmos, MAE rose from 0.2563 to 0.2617 at 8 dimensions (+2.11%). The dataset-wide average therefore does not guarantee the same result at every budget.

The squared-error metric (Brier score) also worsened slightly overall for Historical and Cosmos. Individual agents can also regress. The conclusion is about average MAE, not unchanged performance across every budget, agent or metric.

Conclusion

Based on our results, we did not notice any meaningful performance drop-off when lowering the embedding dimensions from 1,536 to 8, when performance is assessed by average MAE across the 3 datasets tested.

The tested change is simple: take the first 8 values of the native text-embedding-3-small vector and L2-normalize them. These results make 8 dimensions a promising candidate for this sampling-and-IDW pipeline.

That does not mean all information is preserved or that every operating point is lossless. Business-use-case classification, future production data, new judge scores and the proposed weekly sampling policy were not evaluated here. No formal acceptable-loss threshold was pre-specified for MAE.

Details, if you want to go deeper

Sampling, IDW, budgets and fallbacks

Selection uses the same ARM2 novelty/rarity sampler in every arm, with cosine threshold 0.55, cluster TTL 90 and a replay horizon of 10,000. Floors are disabled and throughput is high; final membership is ranked over the full unlabelled schedule and capped by session count. It is label-blind, but is not a fully online admission test.

IDW means “inverse distance weighting”: nearer labelled sessions receive more weight. For a target, the estimator uses up to 8 earlier selected sessions from the same agent, angular distance arccos(cosine) / pi, power 2 and epsilon 1e-6. Exact matches (1 − cosine ≤ 1e-8) are averaged. With no earlier same-agent donor, it uses the earlier global mean; if none exists, it uses prior 0.5.

Illustrative IDW example, not a run result: donor distances 0.1 and 0.2 with labels 1 and 0 yield weights 100 and 25 when epsilon is ignored for simplicity. Normalized weights are 0.8 and 0.2, giving an estimated probability of 0.8. It remains an estimate, not a direct judgment.

Canonical session evidence prioritizes goals, outcomes and tool results, and is bounded to 8,191 cl100k_base tokens. “Full-session” therefore does not mean unlimited verbatim text. There is no fitted reduction transform or train/test reducer fit.
